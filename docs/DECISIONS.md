# Архитектурные решения

## Публичные маршруты без `/v1`

Решение: `POST /api/contact`, health под `/api/health`, statistics под
`/api/metrics`. Причина: точное соответствие исходному PDF и прямому выбору
заказчика от 28 июля 2026 года. Внутреннее имя пакета `api/v1` не является
публичным API.

## PostgreSQL и Redis

Выбран более строгий вариант расширенного ТЗ вместо допустимого в PDF файлового
хранилища. PostgreSQL даёт транзакции и миграции; Redis — атомарный TTL limiter.

## `202 Accepted` и `BackgroundTasks`

Обращение сохраняется до ответа. AI и email выполняются после `202`, а интерфейс
показывает изменение статусов polling-запросами. Это уменьшает latency и
соответствует ТЗ, но не даёт durable delivery; для
production потребуется очередь.

## Устойчивость внешних интеграций

AI всегда имеет детерминированный fallback. Redis rate limit работает fail-open.
SMTP-отправки независимы и сохраняют частичный статус. PostgreSQL остаётся
единственной критической readiness-зависимостью.

Для локальной демонстрации OpenAI-compatible адаптер подключён к llama.cpp с
компактной моделью `Qwen2.5-1.5B-Instruct` в Q4. Это позволяет лучше обрабатывать
русскоязычные обращения и показать реальную AI-функцию
без API-ключей, регистрации и передачи текста обращения внешнему провайдеру.

## Приватность IP и логов

IP преобразуется HMAC-SHA256 с серверной солью и не хранится открыто. Логи
содержат только операционные поля и безопасные идентификаторы, без request body.

## Metrics

`GET /api/metrics` возвращает защищённую JSON-статистику продукта. Без
`METRICS_API_KEY` endpoint маскируется как `404`, чтобы не раскрывать
административную поверхность. Prometheus exposition оставлен вне обязательного
scope.

## Инструменты

Для HTTP-примеров выбрана Postman collection по прямому решению заказчика.
Зависимости фиксирует `uv.lock`; качество проверяют Ruff, strict mypy, pytest и
GitHub Actions.

## Локальная демонстрация

Проект запускается через Docker Compose. Встроенный интерфейс проверяет API,
а Mailpit перехватывает SMTP-уведомления без внешних сервисов и регистраций.
Локальная инструкция является допустимым по исходному заданию способом проверки.
